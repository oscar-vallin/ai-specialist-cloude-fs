# Testing

- Tools: JUnit 5, Mockito, Testcontainers (PostgreSQL), MockMvc or REST-assured. No H2.
- Minimum 70% line coverage on the service layer.
- Integration tests run against a real PostgreSQL via Testcontainers; Testcontainers must work with Podman (document the socket setup in the README).
- Single test: `./mvnw test -Dtest=ClassName#methodName` (run from `backend/`).
- Every endpoint is tested for its success status and its error statuses (400, 401, 403, 404, 409, 422 where applicable).
- Add a contract check that the running API matches `api/openapi.yaml`.
- Must-have business cases: cancel at 47h succeeds; cancel after 48h is rejected with a stable error code (409 or 422); guests cannot place orders; Buy Again uses current price and stock; refunds credit gift points and wallet back.
- Tests are deterministic: fixed clocks for the 48h window, no network, no external book API.
- Record in the README which tests were generated by the ICA "API Testcase generator" agent and which are hand-written.
